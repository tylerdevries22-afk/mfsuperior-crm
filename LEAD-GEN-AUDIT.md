# Lead generation audit — 2026-05-22

Findings from a deep audit of the lead-generation → pipeline → email
flow. Listed in order of impact on the operator's stated symptoms
("generated leads aren't showing up; sent emails aren't showing
either").

## Symptoms → root causes

### "Leads I generate aren't showing up in /leads"

**Cause 1 — Cold-chain filter default hides every restaurant + grocery
lead.** `src/app/(app)/leads/page.tsx` defaulted the cold-chain facet
to `"dry"`, which the WHERE clause translates to
`NOT (tags && ARRAY['refrigerated'])`. Every restaurant generated by
`generateLeadsAction` is auto-tagged `refrigerated` (`actions.ts:1247`),
so the entire restaurant vertical disappeared on page load. **Fixed**:
default flipped to `"all"`; the rail still offers explicit dry / refrig
toggles.

**Cause 2 — Source filter dropdown was missing most generated-lead
labels.** Generated leads carry `source` values like `lead-gen`,
`denver-batch-1`, `research-free-admin`, `starter-pack`, `drive_sync`,
`hunter-search`. The filter only listed 5 sources, so any operator
selecting a source filter would silently see zero results for newly
generated batches. **Fixed**: SOURCES list now covers all 14 known
provenance values.

**Cause 3 — Drive sync can flag leads as `driveSyncOrphan`** when they
don't appear in the latest `*Lead*.xlsx` in the configured Drive
folder. Orphan-flagged leads aren't archived but the operator may
expect to see a UI badge — there isn't one. Mitigation: the cold-chain
+ source fixes above address the more common symptom; the orphan flag
only matters once Drive sync is wired up.

### "Emails I sent aren't showing"

**Cause 4 — Contact-form route silently no-ops when
`RESEND_API_KEY` is missing.** `src/app/api/contact/route.ts` would
log a warning and return success, leaving NO trace anywhere in the
CRM that an email was supposed to fire. The lead was inserted but the
inbox showed nothing. **Fixed**:
  * `sendEmail` now returns a `SendResult` discriminant.
  * Both confirmation + notification outcomes are written as
    `emailEvents` rows (`eventType: "sent"` on success,
    `"failed"` with `metadataJson.kind = "RESEND_API_KEY_missing"`
    or `resend_<status>` otherwise) so /inbox shows the activity.
  * An `auditLog` row captures the full envelope per submission.
  * The API response now includes `{ leadId, emails: { confirmation,
    notification } }` so a calling client can surface the failure.

**Cause 5 — `tickSequences` cron only runs once a day** (`vercel.json`:
`0 13 * * *` = 1pm UTC). A freshly enrolled lead waits up to 24h for
its first draft. **Not changed in this PR** — bumping the schedule
hits Vercel's cron limits and you may want auto-send hours that match
business timezone. Recommendation: change to `0 13,16,19 * * *` or
similar (3 ticks during US business hours).

**Cause 6 — `tickSequences` requires an operator user with a Google
connection OR Resend active**. If neither is present
(`findOperatorUser` returns null), the entire tick aborts with a single
note and zero events. If you signed in but the OAuth scope was denied
for Gmail send, this would also fire. The fix here is operational, not
code: confirm the signed-in user has Gmail scope on /settings.

## Other gaps surfaced (lower priority)

7. **UI lead-gen button caps at 20**. `generateLeadsAction` in
   `actions.ts` enforces `limit ≤ 20`. Plus it samples only ONE
   (industry, county) pair per click (line 1120) — even with all
   industries / counties selected, only 1 cell is queried per
   click. **Addressed by the new `generate50DraftsAction`** which
   bypasses the per-click 20-cap by sourcing from the curated pool
   directly.

8. **`runResearch` fast-mode tags emails as `email-guessed`**, which
   makes them eligible for `wipeGuessedLeadsAction` to archive en
   masse. Operator could lose leads they thought were imported. Not
   fixed; this is a deliberate guardrail in the existing pipeline.

9. **Schema default for template `sendMode` is `auto_send`**, despite
   README claiming "drafts default". New templates fire emails
   immediately on tick. The new bulk action flips templates to draft
   mode before enrolling so the 50-lead batch can't accidentally fire
   live mail.

10. **No CSV preview** for what a generation action will produce.
    `scripts/build-50-draft-csv.ts` was added to write
    `leads-50-draft-batch.csv` — the exact 50 leads the new action
    will insert, so the operator can review before clicking.

## What changed in this PR

* `src/app/(app)/leads/page.tsx` — cold-chain default → `"all"`;
  SOURCES dropdown extended with 9 more provenance labels.
* `src/app/api/contact/route.ts` — contact-form sends are tracked in
  `emailEvents` + `auditLog`; API response surfaces email outcomes.
* `src/app/(app)/admin/actions.ts` — added
  `generate50DraftsAction`: one-click generate-50-from-curated +
  MX-validate + insert + flip templates to draft + auto-enroll.
* `src/app/(app)/admin/_tabs/imports.tsx` — new card surfacing the
  action with a result panel.
* `src/app/(app)/admin/_tabs/types.ts` — typed the new redirect
  params (`g50_*`).
* `scripts/build-50-draft-csv.ts` + `leads-50-draft-batch.csv` — the
  preview CSV.

## How to actually drain the 50 leads as drafts

1. Deploy this branch (`claude/quirky-tesla-b3f5S`).
2. Visit `/admin?tab=imports` and click **Generate 50 + auto-enroll
   as drafts**.
3. Once the redirect lands (≈10s), go to `/admin?tab=tick` and click
   **Manual tick** to fire the sequence engine immediately — it will
   create up to `DAILY_SEND_CAP` (default 20) Gmail drafts in the
   first pass. The remaining 30 will drain across the next ticks /
   the 1pm UTC cron.
4. Review drafts in Gmail; send when ready.

If you don't want to deploy first, you can import
`leads-50-draft-batch.csv` via `/leads/import` for an immediate
preview of the same data.
